How to plan a startup MVP

A minimum viable product is the smallest useful release that tests a real customer problem. Start with the outcome, not the feature list.

1. Define the problem

Identify who has the problem, how they solve it today and what a better outcome looks like. Talk to prospective users before committing to a build.

2. Prioritize one core journey

Map the steps a user needs to complete the primary task. Include only the features essential to that journey, including necessary authentication, data handling and payment safeguards.

3. Choose a realistic architecture

Decide whether a web app, mobile app or both are necessary. Consider integrations, data privacy, maintenance, deployment and budget. A cross-platform approach may help if the same experience is needed on Android and iOS.

4. Agree on measurable success

Define what the release should prove: completed signups, successful bookings, retained users or another relevant outcome. Establish acceptance criteria and a feedback process.

5. Build, test and iterate

Use milestone reviews, test the critical user flows, and release to an appropriate audience. Avoid scaling features until there is evidence of demand.
